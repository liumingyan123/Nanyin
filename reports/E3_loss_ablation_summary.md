## 1. 实验设置（控制变量）

| 项 | 取值 | 说明 |
|---|---|---|
| 数据 | 9 训练曲 → 248 训练窗口；2 验证曲 → 10 验证窗口 | 与 E2 完全一致，窗口/切分逻辑未改 |
| 窗口 | 256 事件 / 训练步长 128（滑动）/ 验证步长 256（非重叠）/ 尾部丢弃 | 与 E2 一致 |
| 掩码 | time-shift 末尾伪标签 + EOS 位用 `IGNORE_INDEX=-100` 屏蔽 | 与 E2 一致，分布损失同样剔除这些位 |
| 模型 | `NanyinBoYaTCN`，3,426,717 可训练参数 | E3 停用 features_head / style_head（参数顺序在三头之后，不影响三头初始化） |
| 优化 | Adam, lr=1e-3, wd=1e-5, StepLR(50, 0.5), grad_clip=1.0, bs=16, 上限 200 epoch, patience=20 | 与 E2 一致 |
| 早停/最优判定 | **监控验证集三路加权 CE**（1.0·pitch + 0.7·duration + 0.7·shift） | 与 E2 损失口径一致，保证跨组、跨阶段可比；分布损失只参与优化不参与判定 |
| 分布损失权重 | 启用组统一 **1.0**（未逐组调参） | 4 项：音级 KL / 调式 KL / 时值分布 KL / IOI 分布 KL |
| 随机种子 | 每组 3 个：2026、2027、2028 | 三组籽贯穿全部组 |

各组配置：`configs/e3_L0.yaml`（基线）、`e3_L1.yaml`、`e3_L2.yaml`、`e3_L3.yaml`、`e3_L4.yaml`、`e3_L5.yaml`（L5 仅框架，不训练）。

**所有分布损失均基于模型最终生成头 logits 计算**（pitch_head → 音级/调式；duration_head → 时值分布；shift_head → IOI 分布），
不使用任何独立辅助头（features_head / style_head 已停用，forward 返回 None）。

## 5. 观测结论

**（1）分布损失没有带来实质性的 best-val 改善。**
四组 best val CE 相对 L0 的降幅依次为 0.07% / 0.12% / 0.35% / 0.22%，全部小于各组内部的三籽极差（0.015~0.024）。
即使表现最好的 L3（6.8570）也无法与 L0 的单个最好种子（6.8788 之外的 2027 籽 6.8957 更差，但 L0 组内最好 6.8788 vs L3 组内最差 6.8657 已经互有重叠）区分开 —— **结论：不能宣称分布损失有效降低了验证损失**。

**（2）唯一较稳定的正向观测：过拟合被延缓（但最优泛化点没变好）。**
末轮 val CE 随启用分布损失单调下降：10.1368（L0）→ 9.9452（L1）→ 9.7485（L2）→ 9.5983（L3）→ **9.1489（L4，−9.7%）**；
早停总轮数由 26.7 增至 27.7~28.0，best epoch 由 6.7 后移到 8.0。
说明分布项起到"柔性正则"作用，让训练后期验证损失恶化得更慢；但 best-val 本身几乎不变，
因此**收益体现在"更耐训"，而非"最终泛化上限提升"**。

**（3）duration 头问题没有解决（重要负向结果，如实记录）。**
E2 基线 duration token 准确率 7.00%（低于多数类基线 ≈10.8%）；本轮 L0~L4 均值分别为
6.93 / 6.71 / 6.91 / 6.53 / 6.69（%），**没有任何一组超过 L0**，三籽最好单值 7.63% 也仅与 E2 持平。
即便专门针对 404 细档长尾设计"粗粒度秒级 bin"的时值/IOI 分布 KL（L3），也没有提升 duration token 级准确率。
实测 L3/L4 的 dur_KL、IOI_KL 在 best 轮已降到 0.056 / 0.070 —— 秒级 bin 聚合后的 GT 直方图非常集中，
模型几乎"免费满足"该约束，**它只能约束粗粒度节奏形状，无法传递细档判别信息**。
→ 归因：duration 头失效的主因是 404 档过细（219 类零样本）与训练/生成任务本身的对齐问题，
不是缺少分布监督；后续应改词表粒度（粗化 / 对数分箱）或改为连续时长回归，而不是继续加分布损失。

**（4）shift 准确率小幅且重复出现的提升。**
23.47（L0）→ 23.60（L1）→ 24.12（L2）→ 24.07（L3）→ **24.35（L4）**，L2/L3/L4 三籽高度一致
（如 L2 的 24.08/24.12/24.16），幅度约 +0.6~0.9pt，是唯一在多组重复出现的正向信号，但幅度仍然很小。

**（5）pitch 准确率在含调式约束的组反而下降。**
35.78（L0）→ 34.68（L2）→ 35.29（L4）；mode_KL 稳定停在 0.16 附近无法继续下降，
原因是"均匀五声音级先验"与真实旋律（含经过音/装饰音）的分布本就不吻合，存在不可消残差，
继续施压会把 pitch 分布往先验拉偏 —— 先验过于粗糙。

**（6）本阶段已知局限（不掩饰）**
- 验证集仅 2 首曲目、10 个非重叠窗口，best-val 判定方差大，跨组比较只能看趋势不能看小数点；
- 窗口级调式真值**全部落在"五空管"**（见训练日志"[调式真值分布]"行），mode 损失实际只施加了单一调式先验；
- 分布损失权重统一取 1.0 且未做超参搜索，存在权重过小导致效果被淹没的可能；
- L5（装饰音）因缺人工核验**未训练**，本报告的 L5 结论只有代码框架与梯度可用性，没有实验数据。

**（7）下一步建议**
优先级：① 改 duration 词表（粗化到 ~32 档或对数分箱 / 连续回归）以直击 7% 准确率问题；
② 扩大验证集（至少 3~4 首）降低 best-val 方差；
③ mode 先验改为平滑分布（带邻音权重）而非均匀五声；
④ 若继续用分布损失，应先做权重搜索（如 1 / 5 / 10）确认量级是否合适。
